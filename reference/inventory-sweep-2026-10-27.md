## Candidates for new entries

1. **Daemons**: the clearest new emitter (logs per instance, documented CPU and memory metrics). Needs a production deployment with a `daemons` block and a container image, which creates billable compute in a project; to check: whether the log drain carries daemon output and with which `source`, and when `vercel.daemon*` metrics appear in `vercel metrics schema`.
2. **Spend Management (budgets)**: a signed webhook at 50/75/100% and an alert history API. Fits as a section of Billing or its own entry. Needs a webhook URL on the budget (a team setting change) and a threshold crossing; the current budget is at 9%, so nothing fires without lowering it.
3. **Schedules**: request metrics already carry schedule dimensions, and the CLI has an execution history. Needs the feature enabled for the team (`schedules_not_enabled`) and published docs.
4. **Custom monitors**: not a new entry; the Alerts entry should note that docs (2026-10-26) describe `custom` threshold monitors on any metric, which this team's schema doesn't offer yet, and that `vercel monitors` replaces `vercel alerts rules`.
5. **Vercel platform status** (`vercel health --json`): not workload telemetry, but the one source that explains drain delays such as the 2026-10-23 "Delays in Logs and Observability data" incident. Could be a short note in the drains material rather than an entry.
